# DTMod — Steam co-op for Devices Tycoon (source code)

Co-op mod for [Devices Tycoon](https://store.steampowered.com/app/2085660/) (Steam appid 2085660): Steam lobbies, one-click
"start game for everybody", shared calendar / AI market / stock prices, ranking, text + voice chat, RU/EN UI.

This repository is **everything that ends up on your PC**. There is no closed part: the installer, the native module and the
UI/game logic are all here, and `verify.py` lets you check that a downloaded `DTMod-Setup.exe` contains exactly this code.

## What is in the installer, and what it does

| Part | File | What it is |
|---|---|---|
| Native module | `src/dtmod.c` (~800 lines, plain C) | A Construct "wrapper extension" DLL (`zz-dtmod-x64.ext.dll`) put next to `Devices Tycoon.exe`. It only calls the flat C exports of `steam_api64.dll`, which the game has already loaded (lobbies, lobby/member data, lobby chat, Steam voice). It has **no network code of its own** (no sockets, no WinHTTP/WinInet), starts no processes and writes only `dtmod.log` (and optional `dtmod_dump_*.txt` debug files) in the game folder. |
| Mod UI + game logic | `src/dtmod.js` (JavaScript, not minified) | Runs inside the game's WebView2 page. Talks to the DLL through `chrome.webview.postMessage`; reads/writes the game's own variables and arrays. It uses no `fetch`, `XMLHttpRequest`, `WebSocket`, `eval` or remote scripts. |
| Installer / patcher | `installer/dtsetup.c`, `patcher.py` | Finds the game (Steam registry + `libraryfolders.vdf`), copies the DLL, **appends** the JS to `www/assets.dat` and repoints `scripts/modernjscheck.js` to it. It writes `dtmod.patch.json` so that "uninstall" restores `assets.dat` byte for byte. "Verify integrity of game files" in Steam also reverts the patch to `assets.dat` (the DLL then stays inert). |

Everything other players receive goes through Steam lobby data / lobby chat only: your company name, the numbers shown in the ranking
(cash, fans, 30-day sales...), chat text, voice, and the shared clock / market / stock tables. Nothing is sent to any server of ours — there is none.

## Build

```
pip install ziglang        # Zig is used only as a C cross-compiler
./build.sh                 # -> build/DTMod-Setup.exe, build/zz-dtmod-x64.ext.dll
```

Tests (Node.js 18+ and python3): `tests/run_all.sh`. They run the UI code against a simulated Steam/game runtime and the installer
against synthetic `assets.dat` containers (including corrupted / read-only cases).

## Verify a downloaded installer

```
python3 verify.py DTMod-Setup.exe
```

It rebuilds `src/dtmod.release.js` from `src/dtmod.js` (the only difference is that the `/*LAB*/` test-helper block with debug hotkeys is
stripped) and checks that these exact bytes are embedded in the exe. The DLL is compiled from `src/dtmod.c` with the command in
`build.sh`; the result is the same size and behaviour but **not bit-for-bit identical** between compiler runs, so for the DLL compare
what matters: its imports (`strings`/`dumpbin /imports` shows only KERNEL32, WINMM, the C runtime and `steam_api64.dll`) and the source.

## Layout

```
src/dtmod.c          native module
src/dtmod.js         mod UI + game logic (dev build with test helpers)
installer/           installer source (payload header is generated by build.sh)
patcher.py           same patch/unpatch logic in Python (used manually and by tests)
build_release.py     dtmod.js -> dtmod.release.js (strips test helpers)
tests/               unit / simulation tests
docs/USER_README.txt end-user readme shipped with the installer (RU/EN)
```

## Notes

* Unofficial fan mod, not affiliated with the game's developer. It modifies one game file (`www/assets.dat`) and adds one DLL; uninstall reverts both.
* The game's own code is not included here.
* Bug reports: please attach `dtmod.log` from the game folder.
